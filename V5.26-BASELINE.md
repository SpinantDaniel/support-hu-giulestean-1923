## Release safety contract

1. All v5.26 work happens on `v5.26-release-hardening`.
2. `main` must remain unchanged until the current remediation step passes verification.
3. Database DDL changes require a committed migration file.
4. Edge Function changes are committed before deployment.
5. Security and Performance Advisors are rerun after DB changes.
6. Production integrity checkpoints are compared after destructive backend changes.
7. Production Vercel commit is verified before and after each release step.
8. A failed verification blocks advancement to the next step.

## Intentionally not fixed by Step 1

This step only establishes version control, recovery reference and release discipline. Signup verification, image optimization, privacy/RLS hardening, destructive CRUD, advisor findings, messaging, legal cleanup, Vercel headers and performance remain unchanged for their scheduled steps.
